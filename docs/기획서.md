## 1. 개요

### 1.1 배경
People 업무 PI 및 E2E 재설계 교육에서 프로세스 나열·도식화를 포스트잇과 수기로 진행해 왔다. 이 방식은
- 작성 결과를 수정·보관·공유하기 어렵고,
- 교육생마다 표기 방식이 달라 비교·취합이 어렵고,
- 진단(문제 유형, 개선 방향) 결과가 도식과 분리되어 관리된다.

### 1.2 목적
웹 브라우저에서 **AS-IS 프로세스를 빠르고 일정한 표기로 그리는** 경량 툴을 만든다.
표로 활동(L6)을 나열하면 순서도가 자동으로 그려지고, 그 위에서 다듬은 결과를 과제 엑셀 양식으로 내보낸다.
진단과 TO-BE 설계는 내보낸 엑셀에서 한다. 툴 안에서 진단·TO-BE까지 하는 기능은 R3 구상으로 남겨 둔다.

### 1.3 교육 운영 시나리오
| 단계 | 시점 | 누가 | 무엇을 | 사용 릴리스 |
|---|---|---|---|---|
| ① 사전과제 배포 | 2026-09-20 | 강사 → 교육생 30명 | `pi-canvas.html` 메일 첨부. L1–L3 체계 내장 | R1 |
| ② 사전과제 작성 | 배포 ~ 9/28 | 교육생 (1인 1개) | **L5 주요 Task 1개를 정하고 L6 활동을 나열**. `.json` 저장 또는 과제 엑셀 양식으로 제출 | R1 |
| ③ 사전 검토 | 교육 전 | 강사 | 제출 파일을 하나씩 열어 검토 (취합 화면 없음) | R2 |

### 1.4 설계 원칙
| 원칙 | 의미 |
|---|---|
| **설치·서버 없음** | HTML 파일 하나. 더블클릭으로 Edge에서 실행하며 사내망/오프라인에서 동작 |
| **파일 호환 보장** | 이전 릴리스에서 저장한 파일은 이후 릴리스에서 그대로 열린다(파일 포맷 버전 관리) |
| **범용성** | People 전용이 아니라 모든 PI 워크숍에 쓸 수 있는 구조. People 는 첫 번째 템플릿 |
| **쉬운 표기법** | BPMN 2.0 핵심 요소만 사용 |
| **목록이 먼저, 그림은 자동** | 표로 입력하면 순서도 초안이 생성되고 그 위에서 다듬는다 |
| **엑셀과 왕복** | 과제 엑셀 양식을 붙여넣으면 순서도가 되고, 내보낸 엑셀을 다시 붙여넣으면 같은 순서도가 된다 |

## 3. E2E 관점 설계 가이드 (툴에 반영할 방법론)

- **Process의 시작과 끝은 고객(현업·직원·지원자) 관점에서 정의한다.**
  예: 경력 채용 = "현업의 채용 요청" → "입사자 첫 출근 및 업무 투입"
- **Swimlane을 기본으로 한다.** 활동의 **담당자** 값이 곧 레인이 된다. People팀 담당자 외에 현업 팀장, 지원자, IT, 총무, 재무, 외부 기관 등이 드러나게 한다. People팀 레인만 가득 찬 것 자체가 진단 포인트다.
- **프로세스화되지 않은 업무도 적는다.** "담당자 판단", "케이스별 상이" 같은 활동도 행으로 남기고 비고에 설명한다.
- **Process 시작 / 종료 / 고객**을 필수 입력으로 두어 범위를 의식하게 한다. 그 밖의 정보(작성자, L1–L5 등)는 선택 입력이다.

### F1. 프로세스 계층 & 과제 정보 (R1)
- **L1–L3 체계는 강사가 지정한 템플릿이 툴에 내장**되어 있다(교육생은 선택만. 설정에 따라 직접 입력 허용).
  - 체계와 운영 설정은 **`config/설정.md`** 에서 관리한다(코드 수정 불필요, 빌드 시 형식 검사).
- 화면 구성
  1. **작성자**: 이름, 소속, 담당 직무 — 모두 선택 입력
  2. **프로세스 (L1 › L2 › L3 › L4 › L5)** — 모두 선택 입력
     - L1 → L2 → L3 을 목록에서 차례로 선택한다.
     - L4 는 직접 입력한다.
     - **L5 주요 Task** 는 직접 입력한다. 이번에 그릴 업무 하나로, 화면에서 가장 눈에 띄게 둔다. (1인 1개. 한 파일 = L5 하나)
  3. **프로세스 속성**

     | 항목 | 필수 | 예시 |

     | Process 시작 (트리거) | ✅ | 현업 팀장의 채용 요청 |

### F2. L6 활동 목록 입력 (R1 핵심)
- 표 형태로 L6 활동을 순서대로 나열한다. **이 표의 칸이 곧 3단 Activity 박스의 상/중/하단**이 된다.

  | 칸 | 필수 | 입력 방식 | 박스 위치 | 예시 |
  |---|---|---|---|---|
  | 순번 | 자동 | 행 순서 | — | 3 |
  | 유형 | ✅ | 활동 / 판단(분기) | 모양 | 판단 |
  | 담당자(역할) | | 자동완성 (한 번 쓴 값 재사용) | 상단 (= Swimlane) | 채용담당 |
  | 활동명 | ✅ | 텍스트, **명사+동사** | 중간 | 채용 요청서 검토 |
  | 시스템/프로그램 | | 칩 다중 선택 + 자유 입력 | 하단 | HRIS, 메일 |
  | Input / Output | | 텍스트 | — | 채용 요청서 / 채용 품의서 |
  | 다음 단계 | | 비우면 다음 순번으로 연결. 판단 행은 `조건→순번` | 연결선 | 승인→4, 반려→1 |
  | 비고 | | 텍스트 | — | 월말에 몰림 |

- 도구 기본 칩은 `config/설정.md` 에서 관리한다(메일, 엑셀, 전화, 메신저, 대면, 종이/출력, 전자결재, HRIS).
- 편집 편의
  - 행 추가, 삭제(되돌리기), 위아래 이동, 행 복제
  - Enter 를 누르면 아래 칸으로 이동, 마지막 행에서 Enter 는 새 행
  - **엑셀 범위를 복사해 붙여넣으면 여러 행이 한 번에 입력된다.** 머리글로 열을 자동 인식한다.
  - (R2) **과제 엑셀 양식(`EXP14` 형식) 그대로 붙여넣기**: 순번 칸이 `시작`/`종료`인 행은 Process 시작/종료 문구로, 설명 칸 안의 `→ 조건 : NN번으로 진행` 은 판단 분기로 인식한다.
- 입력 점검 (저장은 막지 않고 경고만 표시)
  - 필수 칸 누락 (Process 시작/종료, 고객, 활동 1개 이상)
  - 활동명이 명사+동사 형태가 아님(예: "검토" 한 단어, "~함" 문장형) — 팁
  - 판단 행에 조건 있는 다음 단계가 2개 미만
  - 존재하지 않는 순번을 참조함
  - 체계가 바뀌어 선택한 L1–L3 코드가 사라짐
- 권장 분량 안내: L6 활동 **8–20개** (너무 적으면 L5 범위가 좁고, 너무 많으면 L5 를 쪼갤 것). 기준값은 `config/설정.md`.

### F3. 순서도 자동 생성 & 편집 캔버스 (R1 미리보기 → R2 편집)
- 화면 상단 탭 **[1 과제 정보·활동 목록] [2 순서도 편집]** 으로 오간다. **표와 캔버스는 같은 데이터를 보는 두 화면**이다.
- 자동 생성 규칙
  - **담당자별로 Swimlane** 을 만든다(첫 등장 순서). 담당자가 비면 "담당자 미입력" 레인.
  - 순번대로 좌→우로 배치한다.
  - 시작/종료 이벤트를 자동으로 추가한다(시작 → 1번 활동, 다음 단계가 "종료"인 활동과 마지막 행 → 종료).
  - 판단 행은 배타 분기(XOR)로 만든다.
- 표기법: BPMN 2.0 핵심 요소

  | 요소 | 모양 | 용도 | 릴리스 |
  |---|---|---|---|
  | 시작 이벤트 | ○ 얇은 원 | Process 시작 (트리거) | R2 |
  | 종료 이벤트 | ◉ 굵은 원 | Process 종료 (결과) | R2 |
  | Activity | ▭ 둥근 사각형 (3단) | 업무 활동 | R2 |
  | 배타 분기 (XOR) | ◇ | 조건에 따라 하나의 경로 (예: 승인/반려) | R2 |
  | Swimlane | 가로 레인 | 담당자 | R2 |
  | 시퀀스 흐름 | → 실선 화살표 | 순서 (분기 시 조건 라벨) | R2 |
  | 병렬 분기 (AND) | ◇ + | 동시에 여러 경로 진행 | R3 |
  | 주석 | ⌐ 텍스트 | 비고 | R3 |

- 편집 기능 (R2)
  - 팔레트에서 [활동]·[판단]을 끌어다 놓아 추가, 선택한 박스 뒤에 끼워 넣기
  - 박스 연결점을 끌어 연결, 연결선 끝을 끌어 다른 박스로 옮기기
  - 박스를 다른 레인으로 끌면 담당자 변경
  - 레인 추가, 이름 변경(담당자 일괄 변경), 순서 변경
  - 더블클릭으로 이름 수정, Delete 로 삭제(앞뒤 연결 유지), Ctrl+Z / Ctrl+Y
  - 오른쪽 속성 패널에서 활동·연결·시작/종료 이벤트 편집
  - [자동 정렬], [번호 다시 매기기](순서도의 왼쪽→오른쪽 순서로 표 행 순서 정리), 확대/축소, 미니맵
  - 박스 위치·레인 순서는 파일에 저장된다(`process.asis.layout`).
- 순서도 확장 (R3): 병렬 분기(AND), 주석, 레인을 부서 단위로 묶기 · 부서 간 인계 연결선 표시

### F4. 3단 Activity 박스 (R2)
```
┌──────────────────────────┐
│ 채용담당                   │  ← [상단] 담당자 (레인 색상 띠)
├──────────────────────────┤
│     채용 요청서 검토       │  ← [중간] 활동명 (명사+동사), 가장 크게
├──────────────────────────┤
│ [HRIS] [메일] [엑셀]       │  ← [하단] 시스템/프로그램 칩
└──────────────────────────┘
      🔴B  ⏱D   → R        ← (R3 진단 모드) 문제 유형 배지 + 개선 방향
```

### F5. AS-IS 진단 (R3)
> R2 에서는 내보낸 엑셀의 **BDW · ERASK** 칸(드롭다운)에 작성한다.

- 상단 **[진단]** 버튼을 누르면 진단 모드가 켜진다. 박스나 표의 행을 선택하면 우측에 진단 패널이 열린다.
- 입력 항목 (Activity별)

  | 구분 | 항목 | 입력 방식 |
  |---|---|---|
  | 문제 유형 (**BDW**) | Bottleneck / Delay / Waste | 복수 선택 |
  | 개선 방향 (**ERASK**) | Eliminate / Replace / Assist / re**S**tructure / Keep | 단일 선택 |
  | 코멘트 | 문제 원인 / 개선 아이디어 | 자유 텍스트 |
  | 정량 지표 | 처리시간, 대기시간 (분/시간/일) | 숫자 + 단위 (선택 입력) |
  | | 발생 빈도 (월 n회), 투입 인원 | 숫자 (선택 입력) |

- 용어 정의 툴팁은 교육 자료의 정의를 그대로 사용한다(`config/설정.md` 의 `## 진단 용어`).
- 시각화
  - 박스 테두리 색은 개선 방향을 나타낸다(E 빨강, R 파랑, A 보라, S 주황, K 회색).
  - 박스 우상단 배지는 문제 유형을 나타낸다(B, D, W).
  - 범례를 항상 표시한다.
- 진단 요약 (L5 단위)
  - 유형별 건수
  - 총 처리시간, 총 대기시간, **리드타임**
  - **프로세스 효율** = 처리 ÷ 리드타임
  - 월 투입 공수
  - 수작업 도구(메일·엑셀·종이) 비중

### F6. TO-BE 설계 & 비교 (R3)
> R2 에서는 내보낸 엑셀의 **ERASK To-be** 칸에 작성한다.

- **[TO-BE 만들기]** 를 누르면 AS-IS를 복제한다.
  - Eliminate 박스는 점선·흐리게 표시한다.
  - Replace, Assist, reStructure 박스에는 "변경 예정" 표식을 붙인다.
- [비교] 탭
  - AS-IS와 TO-BE를 나란히 표시한다.
  - 활동 수, 리드타임, 효율, 월 공수, 수작업 도구 수의 개선율(%)을 보여준다.

### F7. 저장 / 불러오기 / 내보내기
| 기능 | 릴리스 | 설명 |
|---|---|---|
| 자동 임시저장 | R1 ✅ | 브라우저 저장소에 수시로 저장. 다시 열면 이어서 작성 |
| 파일 저장/열기 (`.json`) | R1 ✅ | **제출용 원본.** 파일명: `L5명_이름.json`. 순서도 배치까지 저장 |

### F8. 강사 취합 화면 (R3)

### F9. 텍스트 가져오기 — 업무 설명서(줄글) → L6 목록 (R3)
- 툴에서 LLM API를 직접 호출하지 않는다(키 노출, 사내망 차단 문제).
- **프롬프트 복사 방식**
  1. 툴이 출력 형식이 지정된 프롬프트 템플릿을 제공한다.
  2. 사용자가 회사에서 허용된 LLM에 템플릿과 업무 설명서를 넣는다.
  3. LLM 결과(표)를 붙여넣으면 F2의 붙여넣기 파서로 L6 목록이 생성된다.
- 사내 LLM 존재 여부와 외부 LLM 사용 정책 확인 필요 (12.3 Q5)

## 7. 데이터 구조 (파일 포맷 v2)

```jsonc
{
  "format": "pi-canvas", "version": 2,
  "meta": { "author": "홍길동", "dept": "People팀", "job": "채용",
            "createdAt": "...", "updatedAt": "...", "appVersion": "..." },

    "templateId": "hr-temp-2026-09",
    "l1": { "code": "HR", "name": "인사" },
    "l2": { "code": "HR.02", "name": "채용" },
    "l3": { "code": "HR.02.02", "name": "경력 채용" },  // 직접 입력한 항목은 code = ""
    "l4": { "code": "", "name": "채용 모집" }           // 항상 직접 입력 (v1.2 추가)
  },
  "process": {                      // L5 주요 Task (1 파일 = 1 L5)
    "name": "채용 요청 및 공고", "startEvent": "...", "endEvent": "...",
    "customer": "...", "owner": "...", "frequency": "...", "description": "...",

      { "id": "a1", "kind": "task", "performer": "현업 팀장",
        "name": "채용 요청서 작성", "tools": ["메일", "엑셀"],
        "input": "", "output": "채용 요청서", "next": [], "note": "" },
      { "id": "a3", "kind": "decision", "performer": "People팀장",
        "name": "채용 승인 여부 판단", "tools": ["전자결재"], "input": "", "output": "",
        "next": [ { "to": "a4", "label": "승인" }, { "to": "a1", "label": "반려" } ], "note": "" }
    ],
    "asis": { "layout": { "lanes": ["현업 팀장", "채용담당"], "pos": { } } },  // R2: 순서도 배치. R3 진단(diag) 추가 예정
```
